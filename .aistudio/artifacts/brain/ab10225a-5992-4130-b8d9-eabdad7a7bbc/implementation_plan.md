# طرح تفصیلی پیاده‌سازی سیستم چند دفترتلفنی و ساختار سلسله‌مراتبی واحد/بخش

این سند، معماری فنی و مراحل پیاده‌سازی قابلیت‌های جدید در نسخه ۳.۰.۰ برنامه دفترچه تلفن سازمانی را شرح می‌دهد. این نسخه تحولی ساختاری از یک دفترچه تلفن تک‌نسخه‌ای به یک سیستم جامع چند دفترتلفنی (مانند تفکیک ۳۱ استان یا دفاتر و شعب مختلف) با فیلدهای پویا، سازمان‌دهی واحدها و بخش‌ها، و خروجی چندبرگه‌ای اکسل است.

---

## ۱. ساختار داده جدید و مدل پایگاه داده (Data Architecture)

### ۱.۱. مدل اطلاعاتی دفترتلفن‌ها (`Phonebook`)
هر دفترتلفن یک موجودیت مستقل با مشخصات زیر خواهد بود:
```typescript
interface Phonebook {
  id: string; // شناسه یکتا (مانند pb-central یا UUID)
  name: string; // عنوان دفترتلفن (مانند "دفتر مرکزی"، "استان تهران")
  isDefault?: boolean; // نشانگر پیش‌فرض بودن
  order: number; // ترتیب نمایش در تب‌ها/منو
  fields: PhonebookField[]; // لیست فیلدهای فعال و ترتیب نمایش آن‌ها
  units: PhonebookUnit[]; // ساختار سلسله‌مراتبی واحدها و بخش‌ها
}

interface PhonebookField {
  id: string; // کلید فیلد در رکورد مخاطب (مانند name, directPhone, internal, voip, custom_...)
  label: string; // عنوان نمایشی فیلد (مانند "نام و نام خانوادگی"، "تلفن مستقیم")
  type: 'text' | 'phone' | 'integer' | 'email';
  visible: boolean; // قابل مشاهده بودن
  order: number; // ترتیب نمایش
  isFixed?: boolean; // آیا فیلد پایه‌ای غیرقابل حذف است (مانند نام و نام خانوادگی)
}

interface PhonebookUnit {
  id: string;
  name: string; // عنوان واحد (جایگزین نام قدیمی "واحد / بخش سازمانی")
  color?: string; // رنگ اختصاصی هدر و کانتینر
  order: number;
  subUnits: PhonebookSubUnit[]; // بخش‌های زیرمجموعه این واحد
}

interface PhonebookSubUnit {
  id: string;
  name: string; // عنوان بخش زیرمجموعه
  order: number;
}
```

### ۱.۲. مدل رکورد مخاطب (`Contact`)
```typescript
interface Contact {
  id?: string;
  phonebookId: string; // شناسه دفترتلفن متصل (مثلاً pb-central)
  'نام و نام خانوادگی': string;
  'واحد': string; // عنوان واحد اصلی
  'بخش'?: string; // عنوان بخش زیرمجموعه (جدید)
  'تلفن مستقیم'?: string;
  'تلفن داخلی'?: string;
  'VoIP'?: string;
  [customFieldKey: string]: any; // فیلدهای سفارشی اضافی متناسب با دفترتلفن
}
```

### ۱.۳. استراتژی ارتقا و مهاجرت داده‌های قبلی (Data Migration)
- در اولین اجرای نسخه ۳.۰.۰، سیستم وجود فیلد `phonebooks` در دیتابیس را بررسی می‌کند.
- در صورت عدم وجود، یک دفترتلفن اولیه با شناسه `pb-central` و نام **«دفتر مرکزی»** به صورت خودکار ایجاد می‌شود.
- تمام مخاطبین موجود در پایگاه داده بدون هیچ‌گونه اتلاف داده، فیلد `phonebookId = 'pb-central'` و فیلد واحد به‌روزرسانی‌شده دریافت خواهند کرد.
- واحدهای سازمانی فعلی به عنوان واحدهای دفتر مرکزی استخراج شده و به صورت مرتب نگهداری می‌شوند.

## ۲. طراحی و تعاملات رابط کاربری (UI/UX)

### ۲.۱. هدر و نوار ناوبری صفحه اصلی (Main Header Switcher)
- نوار تب‌های شیک، ریسپانسیو و اسکرول‌پذیر افقی (به همراه منوی کشویی در صفحات کوچک موبایل) در بالای صفحه اصلی برای سوئیچ سریع بین دفترتلفن‌های مختلف.
- نمایش نشانگر و شمارنده تعداد مخاطبین هر دفترتلفن روی تب مربوطه.
- جستجوی زنده با تمرکز روی دفترتلفن فعال، به همراه گزینه جستجوی سراسری در تمام استان‌ها/دفترتلفن‌ها در صورت نیاز.

### ۲.۲. بخش تنظیمات: مدیریت دفترتلفن‌ها (Phonebook Management)
- افزودن تب/آکاردیون جدید در پنل مدیریت تحت عنوان **«مدیریت دفترتلفن‌ها و ساختار سازمانی»**:
  1. **لیست دفترتلفن‌ها:** امکان افزودن دفترتلفن جدید (نام، اولویت نمایش)، ویرایش نام، و حذف با تاییدیه ایمن.
  2. **تنظیم فیلدهای نمایشی هر دفترتلفن:**
     - فیلدهای پیش‌فرض: «نام و نام خانوادگی»، «تلفن مستقیم»، «تلفن داخلی»، «VoIP».
     - امکان فعال/غیرفعال کردن نمایش هر فیلد (Toggle Visibility).
     - دکمه‌ها و دستگیره‌های درگ و دراپ (Drag & Drop) یا دکمه‌های بالا/پایین برای تغییر ترتیب قرارگیری ستون‌ها.
     - امکان تعریف فیلدهای دلخواه سفارشی جدید.
  3. **مدیریت ساختار واحدها و بخش‌ها (سلسله‌مراتبی):**
     - تغییر عنوان سراسری به **«واحد»**.
     - برای هر واحد: افزودن زیرمجموعه با عنوان **«بخش»**.
     - تنظیم ترتیب نمایش واحدها و بخش‌ها با دستگیره کشیدن و رها کردن (Drag Handle).
     - تعیین رنگ اختصاصی برای هر واحد.

### ۲.۳. ساختار نمایش مخاطبین در نمای لیست و کارت‌ها
- گروه‌بندی اصلی بر اساس **واحد** (با رنگ اختصاصی).
- در زیر هر واحد، تفکیک بر اساس **بخش‌های زیرمجموعه** (Sub-headers یا برچسب‌های تفکیک‌کننده داخل واحد).
- تطبیق جدول دسکتاپ و کارت‌های موبایل با فیلدهای فعال دفترتلفن جاری و حفظ ثبات ارتفاع سلول‌های کارت در موبایل.

### ۲.۴. فرم افزودن و ویرایش مخاطب
- **فیلد دفترتلفن:** منوی کشویی در بالاترین نقطه فرم با انتخاب پیش‌فرض روی دفترتلفن جاری.
- **فیلد واحد:** منوی جستجوپذیر واحدهای مربوط به دفترتلفن انتخاب‌شده با امکان ایجاد سریع واحد جدید.
- **فیلد بخش:** منوی هوشمند وابسته (Cascading) که بلافاصله پس از انتخاب واحد، لیست بخش‌های تعریف‌شده آن واحد را نشان می‌دهد؛ همراه با گزینه «➕ افزودن بخش جدید» در جا بدون نیاز به خروج از فرم.
- ورودی‌های اطلاعات تماس متناسب با فیلدهای فعال همان دفترتلفن مرتب و فیلتر می‌شوند.

## ۳. ارتقای ماژول خروجی و ورودی (Excel & Backup)

### ۳.۱. ماژول خروجی اکسل چندبرگه‌ای (Multi-Sheet Excel Export)
- ایجاد مودال انتخاب دفترتلفن‌ها هنگام کلیک روی دکمه خروجی اکسل:
  - چک‌باکس انتخاب همه / انتخاب تکی دفترتلفن‌ها (مثلاً انتخاب ۳ استان دلخواه یا تمام ۳۱ دفترتلفن).
- ساخت فایل اکسل با کتابخانه `ExcelJS` به صورت کاملاً آفلاین و راست‌به‌چپ (RTL):
  - **ایجاد یک شیت مجزا برای هر دفترتلفن انتخاب‌شده** با نام همان دفترتلفن (مثلاً شیت «دفتر مرکزی»، شیت «تهران»، شیت «اصفهان»).
  - اعمال قالب‌بندی سازمانی، هدر اختصاصی، رنگ‌بندی هر واحد، نمایش بخش‌های زیرمجموعه و فرمت متنی شماره‌ها برای جلوگیری از حذف صفر ابتدا.
  - ایجاد یک برگه پایانی اختیاری «خلاصه کل» در صورت نیاز.

### ۳.۲. ارتقای نسخه پشتیبان JSON (Backup & Restore)
- ساختار پشتیبان‌گیری به‌گونه‌ای ارتقا می‌یابد که تمامی دفترتلفن‌ها، تنظیمات فیلدها، ساختار سلسله‌مراتبی واحدها/بخش‌ها و مخاطبین را با فرمت استاندارد نسخه ۳ صادر کند.
- ماژول بازیابی (Restore) به صورت هوشمند از هر دو نوع فایل قدیمی (نسخه‌های ۱ و ۲ تک‌دفترتلفنی) و نسخه جدید ۳ به صورت خودکار و بدون خطا پشتیبانی خواهد کرد.

## ۴. مراحل گام‌به‌گام پیاده‌سازی

1. **فاز ۱: پایگاه داده و مهاجرت ساختار داده**
   - پیاده‌سازی کلاس و مخزن مدیریت داده‌های چند دفترتلفنی در IndexedDB و LocalStorage.
   - اعمال الگوریتم مهاجرت داده‌های قدیمی به دفترتلفن پیش‌فرض «دفتر مرکزی».

2. **فاز ۲: رابط مدیریت دفترتلفن‌ها، واحدها و بخش‌ها در تنظیمات**
   - ساخت UI مدیریت دفترتلفن‌ها (ایجاد، حذف، تغییر نام).
   - ساخت UI تنظیم فیلدها با قابلیت Drag & Drop / Reorder.
   - ساخت کامپوننت سلسله‌مراتبی مدیریت واحد و بخش‌ها با امکان تغییر ترتیب.

3. **فاز ۳: بازطراحی صفحه اصلی و لیست مخاطبین**
   - پیاده‌سازی نوار تب‌های سوئیچ دفترتلفن در هدر.
   - به‌روزرسانی رندرینگ جدول دسکتاپ و کارت‌های موبایل برای نمایش چند دفترتلفنی و تفکیک بخش‌های زیر واحد.

4. **فاز ۴: فرم افزودن / ویرایش مخاطب**
   - افزودن انتخابگر دفترتلفن، واحد و بخش با لود پویا و ایجاد سریع درجا.

5. **فاز ۵: ماژول خروجی اکسل و پشتیبان‌گیری**
   - طراحی مودال انتخاب دفترتلفن‌ها برای اکسل.
   - پیاده‌سازی ایجاد شیت‌های چندگانه در ExcelJS با نام هر دفترتلفن و ساختار سلسله‌مراتبی.
   - به‌روزرسانی صادرکننده و بازیابی‌کننده JSON.

6. **فاز ۶: اعتبارسنجی، تست و به‌روزرسانی نسخه**
   - تست کامل مهاجرت اطلاعات موجود، حفظ عملکرد ۱۰۰٪ آفلاین، اعتبارسنجی در محیط‌های موبایل و دسکتاپ، و به‌روزرسانی `Version Info.json` به نسخه ۳.۰.۰.
